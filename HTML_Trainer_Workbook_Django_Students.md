# HTML Trainer Workbook
## Industry-oriented HTML for Python, Django and Django REST Framework students

**Audience:** Beginners who have completed Python and are moving towards Django/DRF and frontend development  
**Suggested duration:** 6–8 sessions (approximately 12–16 hours)  
**Teaching approach:** Explain the purpose of each element, demonstrate it in a small page, then use it in a realistic application screen.

---

## 1. Trainer's direction: what should students learn?

HTML is not a programming language. It is a **markup language used to describe the structure and meaning of web content**.

For a Django student, HTML is the structure of the pages that users see and interact with. Django can generate HTML using templates, send data into those templates, and receive form submissions. Later, JavaScript and React can update and build interfaces using the same underlying HTML concepts.

### Industry-oriented learning outcomes

By the end of this module, students should be able to:

1. Create a valid HTML5 document and organize files and assets.
2. Structure a page using semantic HTML instead of using `<div>` for everything.
3. Build navigation, content sections, cards, lists, tables and data pages.
4. Build accessible forms with suitable input types, labels and validation attributes.
5. Understand how a browser submits form data using `GET` and `POST`.
6. Use images, links, buttons and common interactive HTML elements correctly.
7. Apply basic accessibility, SEO and responsive-content practices.
8. Read and understand HTML generated by Bootstrap and React.
9. Connect an HTML form to a Django view and understand how Django templates render dynamic content.

### What employers expect at this level

Students should be comfortable reading and writing clean HTML, creating common application screens, using forms correctly, understanding semantic structure, and debugging markup in browser developer tools. HTML alone does not make someone a frontend developer; it is the foundation for CSS, JavaScript, responsive UI work and frameworks.

**Teaching principle:** Do not spend the whole module memorizing every HTML tag. Teach the commonly used elements deeply and introduce specialized elements as awareness topics.

# PART A — HTML foundations

## 3. How the web page works

Explain the basic flow:

1. A browser requests a page from a server.
2. The server returns an HTML document (and may also return CSS, JavaScript and media files).
3. The browser parses the HTML and builds the document structure.
4. CSS controls presentation and layout.
5. JavaScript adds behaviour and interactivity.

For a Django application:

1. The browser requests a URL.
2. Django URL routing selects a view.
3. The view may read data from the database.
4. Django renders a template or returns an API response.
5. The browser displays HTML, or a frontend application uses API data to render the interface.

**Important distinction:** Django templates generate HTML on the server. Django REST Framework usually returns data such as JSON; a frontend built with HTML/CSS/JavaScript or React consumes that data.

## 4. HTML syntax and terminology

Teach these terms:

- **Element:** The complete unit, usually an opening tag, content and closing tag.
- **Tag:** The markup inside angle brackets.
- **Attribute:** Additional information written in the opening tag.
- **Nested element:** An element placed inside another element.
- **Parent / child / sibling:** Relationships between nested elements.
- **Empty (void) element:** An element that does not have a closing tag, such as `<img>` or `<input>`.

Example:

```html
<p class="message">Welcome to the course</p>
```

- `p` — element name
- `class` — attribute name
- `message` — attribute value
- `Welcome to the course` — text content

### Basic rules

- Use lowercase tag names.
- Close non-void elements properly.
- Nest elements correctly.
- Put attribute values in quotes.
- Use meaningful indentation.
- Use comments only when they add useful explanation.
- Use one clear page title and a logical heading hierarchy.

```html
<!-- This is an HTML comment -->
<h1>Python Django Program</h1>
<p>Learn backend web development.</p>
```

## 5. HTML document structure

Every beginner should be able to write this without copying.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Student Portal</title>
    <meta name="description" content="Student learning portal">
</head>
<body>
    <header>
        <h1>Student Portal</h1>
    </header>

    <main>
        <p>Welcome to the portal.</p>
    </main>

    <footer>
        <p>&copy; 2026 Student Portal</p>
    </footer>
</body>
</html>
```

### Explain the important parts

| Element / attribute | Purpose |
|---|---|
| `<!DOCTYPE html>` | Tells the browser to use modern HTML parsing mode |
| `<html lang="en">` | Root element; declares the document language |
| `<head>` | Metadata and linked resources; not the visible page content |
| `<meta charset="UTF-8">` | Character encoding |
| viewport meta | Helps the page use the device viewport on mobile |
| `<title>` | Browser tab title; useful for search results |
| description meta | Short page description that may be used in search snippets |
| `<body>` | Visible document content |

**Trainer note:** The viewport meta tag does not itself make a page responsive. Responsive layout is mainly handled with CSS.

# PART B — Common HTML elements

## 6. Headings and text elements

| Element | Use |
|---|---|
| `<h1>` to `<h6>` | Headings, from highest to lowest level |
| `<p>` | Paragraph |
| `<br>` | Line break when a line break is meaningful |
| `<hr>` | Thematic break between sections |
| `<strong>` | Important text |
| `<em>` | Emphasized text |
| `<b>` | Draw attention without adding importance |
| `<i>` | Alternate voice or term; not simply a styling shortcut |
| `<mark>` | Highlighted text |
| `<small>` | Side comments or fine print |
| `<sub>` / `<sup>` | Subscript / superscript |
| `<pre>` / `<code>` | Preformatted text and code snippets |

Example:

```html
<h1>Django Placement Program</h1>
<h2>Course Overview</h2>
<p>Learn backend development using Python and Django.</p>
<p><strong>Duration:</strong> 6 months</p>
<p><em>Admissions are open.</em></p>
```

**Teaching point:** Do not select heading tags just because of their default font size. Use them to represent the document outline; CSS controls appearance.

## 7. Links and navigation

Important element: `<a>`

```html
<a href="https://www.example.com">Visit website</a>
<a href="about.html">About us</a>
<a href="#contact">Go to contact section</a>
<a href="mailto:info@example.com">Send email</a>
<a href="tel:+910000000000">Call us</a>
```

### Important attributes

- `href` — destination.
- `target="_blank"` — opens in a new browsing context.
- `rel="noopener"` — use with `target="_blank"` as a safe default.
- `id` — can be used as an in-page destination.

```html
<a href="https://www.example.com"
   target="_blank"
   rel="noopener">
    Open website
</a>
```

### Navigation example

```html
<nav aria-label="Main navigation">
    <a href="/">Home</a>
    <a href="/courses/">Courses</a>
    <a href="/about/">About</a>
    <a href="/contact/">Contact</a>
</nav>
```

Explain the difference:

- A **link** navigates to another resource or location.
- A **button** performs an action on the current page, such as submitting a form or opening a dialog.

## 8. Lists

### Unordered list — `<ul>`

```html
<h2>Technologies</h2>
<ul>
    <li>Python</li>
    <li>Django</li>
    <li>MySQL</li>
</ul>
```

### Ordered list — `<ol>`

```html
<h2>Course stages</h2>
<ol>
    <li>Python</li>
    <li>Database</li>
    <li>Django REST Framework</li>
</ol>
```

### Description list — `<dl>`, `<dt>`, `<dd>`

```html
<dl>
    <dt>DRF</dt>
    <dd>Django REST Framework</dd>

    <dt>API</dt>
    <dd>Application Programming Interface</dd>
</dl>
```

Teach nested lists after students understand the basic list structure.

## 9. Images and file paths

Important element: `<img>`

```html
<img src="images/classroom.jpg"
     alt="Students attending a Python class"
     width="400">
```

Important attributes:

- `src` — image path or URL.
- `alt` — text alternative describing the image's purpose.
- `width` and `height` — dimensions; providing dimensions helps avoid layout shifts.
- `loading="lazy"` — can defer loading of off-screen images.

```html
<img src="images/course-banner.jpg"
     alt="Django course banner"
     width="1200"
     height="500"
     loading="lazy">
```

### Relative path examples

```html
<img src="images/logo.png" alt="Institute logo">
<a href="pages/about.html">About</a>
```

Explain the difference between relative paths and absolute URLs.

**Accessibility note:** Do not write `alt="image"` for every image. Describe meaningful images. For a purely decorative image, use `alt=""`.

## 10. Tables

Use tables for tabular data, not for page layout.

Important elements:

`<table>`, `<caption>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<th>`, `<td>`

```html
<table>
    <caption>Student details</caption>
    <thead>
        <tr>
            <th scope="col">Name</th>
            <th scope="col">Course</th>
            <th scope="col">Status</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Anu</td>
            <td>Django</td>
            <td>Active</td>
        </tr>
        <tr>
            <td>Rahul</td>
            <td>Data Analytics</td>
            <td>Active</td>
        </tr>
    </tbody>
</table>
```

Explain `scope="col"` and `scope="row"` as ways to associate table headings with data cells.

# PART C — Semantic HTML and professional page structure

## 11. Why semantic HTML matters

Semantic HTML means choosing elements according to the meaning and role of the content, not merely how they look.

Benefits:

- Makes the page easier for developers to understand and maintain.
- Gives browsers and assistive technologies meaningful structure.
- Supports keyboard and screen-reader usability.
- Helps search engines interpret page content.
- Makes application markup more consistent.

### Important semantic elements

| Element | Typical purpose |
|---|---|
| `<header>` | Introductory content for a page or section |
| `<nav>` | Main navigation links |
| `<main>` | Main content of the page |
| `<section>` | Thematic section, normally with a heading |
| `<article>` | Independent, reusable content such as a post or course card |
| `<aside>` | Related or supplementary content |
| `<footer>` | Footer information for a page or section |
| `<figure>` | Self-contained media or illustration |
| `<figcaption>` | Caption for a figure |
| `<address>` | Contact information for the nearest relevant page or article |
| `<time>` | Machine-readable date or time |

### Example: course listing page

```html
<body>
    <header>
        <h1>Learning Portal</h1>
        <nav aria-label="Main navigation">
            <a href="/">Home</a>
            <a href="/courses/">Courses</a>
            <a href="/login/">Login</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>Available courses</h2>

            <article>
                <h3>Python Django</h3>
                <p>Learn backend web development.</p>
                <a href="/courses/django/">View course</a>
            </article>

            <article>
                <h3>Data Analytics</h3>
                <p>Learn to work with and understand data.</p>
                <a href="/courses/data-analytics/">View course</a>
            </article>
        </section>
    </main>

    <footer>
        <p>&copy; 2026 Learning Portal</p>
    </footer>
</body>
```

### `div` and `span`

- `<div>` is a generic block container.
- `<span>` is a generic inline container.
- They are useful when no more meaningful semantic element fits.
- Do not build every page using only `<div>` elements when semantic elements are appropriate.

**Trainer activity:** Ask students to identify the page header, navigation, main content, independent cards and footer in the example.

# PART D — Forms: the most important HTML topic for Django students

## 12. Understanding HTML forms

A form collects information from a user and submits it to a destination.

Common real-world uses:

- Registration
- Login
- Contact and enquiry forms
- Course applications
- Booking forms
- Search and filter forms
- Expense entry
- File uploads

### Basic form structure

```html
<form action="/register/" method="post">
    <label for="full_name">Full name</label>
    <input type="text" id="full_name" name="full_name">

    <button type="submit">Register</button>
</form>
```

Explain every part:

- `<form>` groups controls and defines submission behaviour.
- `action` tells the browser where to submit.
- `method` defines the HTTP method.
- `name` is the key used when form data is submitted.
- `id` uniquely identifies an element in the document.
- `<label>` gives a control an accessible name.
- `for` on a label should match the control's `id`.
- `type="submit"` submits the form.

**Critical Django connection:** The `name` attribute is essential. Django reads submitted values using keys such as `request.POST.get("full_name")`. An `id` by itself does not send a value to the server.

## 13. Common input types

| Input type | Typical use |
|---|---|
| `text` | Name, title |
| `email` | Email address |
| `password` | Password |
| `number` | Numeric quantity |
| `tel` | Telephone number |
| `date` | Date |
| `time` | Time |
| `datetime-local` | Local date and time |
| `file` | File upload |
| `checkbox` | Select one or more independent options |
| `radio` | Select one option from a group |
| `search` | Search query |
| `url` | Website URL |
| `range` | Slider value |
| `color` | Colour selection |
| `hidden` | Hidden form value (not secure storage) |
| `submit` | Submit control |
| `reset` | Restore initial form values; use sparingly |

Example:

```html
<form>
    <label for="name">Name</label>
    <input type="text" id="name" name="name" required>

    <label for="email">Email</label>
    <input type="email" id="email" name="email" required>

    <label for="age">Age</label>
    <input type="number" id="age" name="age" min="18" max="60">

    <label for="joining_date">Joining date</label>
    <input type="date" id="joining_date" name="joining_date">

    <button type="submit">Save</button>
</form>
```

## 14. Other form elements

### Textarea

```html
<label for="address">Address</label>
<textarea id="address" name="address" rows="4"></textarea>
```

### Select and option

```html
<label for="course">Choose course</label>
<select id="course" name="course">
    <option value="">Select a course</option>
    <option value="django">Python Django</option>
    <option value="data">Data Analytics</option>
</select>
```

### Radio buttons

```html
<p>Preferred batch</p>

<input type="radio" id="morning" name="batch" value="morning">
<label for="morning">Morning</label>

<input type="radio" id="evening" name="batch" value="evening">
<label for="evening">Evening</label>
```

Radio buttons in one group share the same `name`.

### Checkboxes

```html
<p>Technologies known</p>

<input type="checkbox" id="python" name="skills" value="python">
<label for="python">Python</label>

<input type="checkbox" id="django" name="skills" value="django">
<label for="django">Django</label>
```

Checkboxes allow multiple independent selections.

### Fieldset and legend

```html
<fieldset>
    <legend>Personal details</legend>

    <label for="student_name">Name</label>
    <input type="text" id="student_name" name="student_name">
</fieldset>
```

Use these to group related controls.

### File upload

```html
<form action="/upload/" method="post" enctype="multipart/form-data">
    <label for="resume">Upload resume</label>
    <input type="file" id="resume" name="resume" accept=".pdf,.doc,.docx">
    <button type="submit">Upload</button>
</form>
```

Teach these points:

- File upload forms need `method="post"`.
- File upload forms need `enctype="multipart/form-data"`.
- In Django, uploaded files are accessed through `request.FILES`.
- The `accept` attribute is a file-picker hint, not a security check. Validate file type and size on the server.

## 15. Important form attributes

| Attribute | Purpose |
|---|---|
| `name` | Key used during form submission |
| `id` | Unique element identifier |
| `value` | Submitted value or initial value |
| `placeholder` | Short hint inside a control; not a replacement for a label |
| `required` | Browser requires a value before submission |
| `min` / `max` | Numeric or date range boundaries |
| `minlength` / `maxlength` | Text length constraints |
| `step` | Permitted increment for numeric/date-time controls |
| `pattern` | Pattern constraint for supported text inputs |
| `checked` | Initially checks a checkbox or radio button |
| `selected` | Initially selects an option |
| `readonly` | Value cannot be edited, but is generally submitted |
| `disabled` | Control is disabled and is not submitted |
| `multiple` | Allows multiple values/files where supported |
| `autocomplete` | Gives the browser hints for autofill |
| `autofocus` | Requests initial focus; use carefully |
| `accept` | File-picker type hint |
| `enctype` | Form data encoding |
| `action` | Submission destination |
| `method` | Submission method |

### Browser-side validation example

```html
<form>
    <label for="email_address">Email</label>
    <input type="email"
           id="email_address"
           name="email"
           required>

    <label for="phone">Phone</label>
    <input type="tel"
           id="phone"
           name="phone"
           required
           minlength="10"
           maxlength="15">

    <label for="password">Password</label>
    <input type="password"
           id="password"
           name="password"
           required
           minlength="8">

    <button type="submit">Submit</button>
</form>
```

**Very important:** Browser validation improves user experience. It is not a security boundary. Always validate data on the server. Django forms/serializers and model/business validation remain necessary.

## 16. GET vs POST — explain with a browser demonstration

### GET

- Commonly used to request or filter information.
- Form values are generally appended to the URL as query parameters.
- Useful for search and filter pages.
- Avoid using it for passwords or sensitive information.

```html
<form action="/courses/" method="get">
    <label for="keyword">Search courses</label>
    <input type="search" id="keyword" name="q">
    <button type="submit">Search</button>
</form>
```

A submitted search may produce a URL such as:

`/courses/?q=django`

### POST

- Sends form data in the request body.
- Commonly used for create/update actions and sensitive form workflows.
- Does not automatically make data secure; HTTPS is still required.
- In Django, POST forms that change server state must include CSRF protection.

```html
<form action="/contact/" method="post">
    <!-- Django template: include the CSRF token here -->
    <label for="message">Message</label>
    <textarea id="message" name="message"></textarea>
    <button type="submit">Send</button>
</form>
```

### Django template connection

```html
<form method="post">
    {% csrf_token %}

    <label for="name">Name</label>
    <input type="text" id="name" name="name">

    <button type="submit">Submit</button>
</form>
```

Explain that `{% csrf_token %}` is Django template syntax, not an HTML tag. It protects Django POST form submissions against cross-site request forgery.

A simple view-side illustration:

```python
def register(request):
    if request.method == "POST":
        name = request.POST.get("name")
        # Validate the data before saving it.
```

For a DRF project, explain that an HTML form can submit to a backend endpoint, but API authentication, CSRF behaviour and request formats depend on the authentication and API design. Do not teach students that every DRF endpoint accepts a normal browser form submission.

# PART E — Modern practical HTML

## 17. Buttons

```html
<button type="button">Open menu</button>
<button type="submit">Save</button>
<button type="reset">Reset</button>
```

- `type="button"` does not submit the surrounding form by default.
- `type="submit"` submits the form.
- `type="reset"` resets controls to their initial values.

Always specify the button type when the button is inside a form, so its behaviour is clear.

## 18. Audio and video

```html
<video controls width="500">
    <source src="intro.mp4" type="video/mp4">
    Your browser does not support the video element.
</video>
```

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
    Your browser does not support the audio element.
</audio>
```

Introduce `controls`, `autoplay`, `muted`, `loop`, `poster` and captions using `<track>`. Explain that autoplay should not be used casually, especially with sound.

## 19. Useful interactive elements

### Details and summary

```html
<details>
    <summary>What is Django?</summary>
    <p>Django is a Python web framework.</p>
</details>
```

### Dialog (introductory awareness)

```html
<dialog open>
    <p>Registration completed.</p>
</dialog>
```

Explain that a production modal needs appropriate keyboard behaviour, focus management and a way to close it. JavaScript is normally used to open and close a dialog.

## 20. Script and stylesheet linking

Students should recognize these tags even if CSS and JavaScript are taught separately.

```html
<link rel="stylesheet" href="css/style.css">
<script src="js/app.js" defer></script>
```

Explain:

- `<link>` commonly connects an external stylesheet.
- `<script>` loads or contains JavaScript.
- `defer` downloads the external script while HTML parsing continues, then runs it after parsing.
- `type="module"` is used for JavaScript modules.

```html
<script type="module" src="js/main.js"></script>
```

Do not teach inline styling or inline JavaScript as the normal project structure.

# PART F — Professional quality: accessibility, SEO and responsive readiness

## 21. Accessibility checklist

Accessibility should be introduced during the relevant lessons, not left until the final class.

- Use semantic elements for their intended purpose.
- Use headings in a meaningful hierarchy.
- Give form controls visible, associated labels.
- Use useful link text; avoid vague text such as “click here” when context is unclear.
- Add meaningful `alt` text to informative images.
- Ensure interactive controls can be reached and used with a keyboard.
- Do not remove visible focus indicators without providing a clear alternative.
- Use table headings (`<th>`) for data tables.
- Use buttons for actions and links for navigation.
- Keep the DOM/source order logical.

### Label example

Good:

```html
<label for="student_email">Email address</label>
<input type="email" id="student_email" name="email">
```

Avoid relying only on:

```html
<input type="email" placeholder="Enter email">
```

A placeholder is a hint, not a proper substitute for a label.

## 22. SEO-friendly HTML basics

Teach only the practical foundations:

- A meaningful and unique `<title>` for each page.
- A useful meta description.
- One clear main heading and logical subheadings.
- Semantic page structure.
- Descriptive link text.
- Useful alternative text for meaningful images.
- Correct language declaration on `<html>`.
- Meaningful page content rather than a page made entirely of generic containers.

Do not promise students that semantic tags automatically guarantee a high search ranking. They improve structure and interpretation; SEO depends on many other factors.

## 23. Responsive-content basics

HTML provides useful building blocks, but responsive design is primarily a CSS topic.

Introduce:

- The viewport meta tag.
- Avoiding fixed-width assumptions in content.
- Image `width` and `height` attributes to reserve space.
- `srcset` and `sizes` as awareness topics for serving different image sizes.
- The `<picture>` element for art direction or alternate image formats.

Example:

```html
<picture>
    <source media="(max-width: 600px)" srcset="images/banner-small.jpg">
    <img src="images/banner-large.jpg"
         alt="Students learning web development"
         width="1200"
         height="500">
</picture>
```

The CSS module should cover flexible layouts, media queries, Flexbox and Grid in depth.

# PART G — HTML for Django and React workflows

## 24. HTML concepts Django students must understand

| HTML concept | Django connection |
|---|---|
| `form` | Submits user data to a Django URL |
| `action` | Maps to a URL handled by a Django view |
| `method` | Commonly GET or POST |
| `name` | Key used in `request.GET` or `request.POST` |
| `value` | Submitted value |
| `enctype` | Required for browser file uploads |
| `label` and `id` | Accessible form controls |
| `table`, `tr`, `td` | Display database records |
| `a href` | Navigate between application pages |
| `img src` | Display static or uploaded media |
| `class` | CSS/Bootstrap styling hook |
| `data-*` | Store custom data for JavaScript behaviour |

### Django template awareness

Students should recognize the following as Django template syntax, not HTML:

```html
{% for student in students %}
    <p>{{ student.name }}</p>
{% endfor %}
```

```html
{% if user.is_authenticated %}
    <p>Welcome, {{ user.username }}</p>
{% endif %}
```

Teach these only as a bridge if the batch is about to start Django templates. Keep the HTML and Django template concepts clearly separated.

### Static files awareness

```html
{% load static %}
<link rel="stylesheet" href="{% static 'css/style.css' %}">
<img src="{% static 'images/logo.png' %}" alt="Institute logo">
```

Again, `{% load static %}` and `{% static %}` are Django template features.

## 25. HTML concepts students will see in Bootstrap and React

- Bootstrap classes are commonly added through the `class` attribute.
- React components ultimately render DOM elements such as `div`, `form`, `input`, `button`, `section` and `article`.
- React uses JSX, which looks similar to HTML but follows JavaScript syntax rules.
- In JSX, `className` is used instead of HTML's `class`, and `htmlFor` instead of `for`.
- HTML form fundamentals (`name`, `value`, `type`, labels and button types) remain important when building React forms.

Do not teach JSX during the HTML module. Just explain that strong HTML knowledge makes JSX easier to understand.

# PART H — Tags to prioritize

## 26. Core tags: students should write these confidently

| Category | Tags |
|---|---|
| Document | `html`, `head`, `title`, `meta`, `body` |
| Text | `h1`–`h6`, `p`, `br`, `hr`, `strong`, `em`, `span`, `div` |
| Navigation | `a`, `nav` |
| Lists | `ul`, `ol`, `li`, `dl`, `dt`, `dd` |
| Media | `img`, `picture`, `source`, `video`, `audio` |
| Tables | `table`, `caption`, `thead`, `tbody`, `tr`, `th`, `td` |
| Forms | `form`, `label`, `input`, `textarea`, `select`, `option`, `button`, `fieldset`, `legend` |
| Semantics | `header`, `main`, `section`, `article`, `aside`, `footer`, `figure`, `figcaption` |
| Interactive | `details`, `summary`, `dialog` |
| Resource linking | `link`, `script` |

## 27. Awareness / learn when needed

`abbr`, `blockquote`, `cite`, `code`, `pre`, `time`, `address`, `mark`, `small`, `sub`, `sup`, `progress`, `meter`, `datalist`, `output`, `template`, `canvas`, `iframe`, `track`, `map`, `area`.

Students do not need to memorize every specialized element during the first HTML module. They should know how to find and use documentation.

## 28. Obsolete or discouraged elements

Do not teach these as modern practice:

- `<font>` — use CSS for typography.
- `<center>` — use CSS for alignment.
- `<marquee>` — obsolete; use CSS animation if appropriate.
- `<big>` — obsolete.
- `<strike>` — obsolete; use appropriate semantic markup or CSS.
- `<frameset>` and `<frame>` — obsolete.
- Tables for page layout — use CSS layout systems.
- Repeated `<br>` tags to create spacing — use CSS margin and padding.

# PART J — Trainer's delivery notes

## 35. Recommended classroom method

For each concept:

1. **Explain the purpose:** What problem does this element solve?
2. **Show a real example:** Use a registration page, course page, dashboard or booking form.
3. **Type it live:** Build the example in VS Code instead of only showing slides.
4. **Inspect it:** Open it in the browser and use Inspect / Developer Tools.
5. **Break it intentionally:** Remove a closing tag, label association or `name` attribute and ask students to identify the issue.
6. **Give a small task:** Let students modify the page independently.
7. **Review code quality:** Check indentation, semantic choices, labels, naming and accessibility.

### Suggested live demonstrations

- Change `<div>`-only markup into semantic page structure.
- Show how a link differs from a button.
- Submit a GET form and observe the query string in the URL.
- Remove the `name` attribute and explain why the value is not submitted under the expected key.
- Compare `disabled` and `readonly`.
- Upload a file and explain `multipart/form-data`.
- Use browser Inspect to identify elements and attributes.
- Use keyboard Tab and Enter/Space to test navigation and controls.

## 36. Common student mistakes to watch for

- Writing all page content inside `<div>` without considering semantics.
- Using headings only to make text large.
- Forgetting `alt` text on meaningful images.
- Using placeholder text instead of labels.
- Forgetting `name` on form controls.
- Giving radio buttons different `name` values when they should be one group.
- Using a link when an action button is required, or vice versa.
- Forgetting `enctype="multipart/form-data"` for uploads.
- Believing browser-side validation replaces backend validation.
- Using tables to position page elements.
- Using fixed dimensions everywhere before learning responsive CSS.
- Confusing HTML with Django template syntax or JSX.

# PART K — What to teach next

After HTML, follow this sequence:

1. **CSS fundamentals:** selectors, specificity, box model, units, colours, typography, display, positioning.
2. **CSS layouts:** Flexbox, Grid, responsive design and media queries.
3. **Bootstrap:** containers, grid system, utilities, navbar, cards, tables, forms, buttons and responsive components.
4. **JavaScript fundamentals:** variables, conditions, loops, functions, arrays, objects, DOM, events, fetch and JSON.
5. **React:** components, JSX, props, state, events, forms, hooks, routing and API integration.

For a Django/DRF placement-focused course, make students build a few real screens before moving to React. They should understand the structure of a form, table, navigation bar, course card and dashboard before asking a component framework to generate them.
